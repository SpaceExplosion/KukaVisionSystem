# Роботизированная ячейка Pick-and-Place: KUKA + OpenCV

Реализация ТЗ: внешний ПК обрабатывает видеопоток с камеры, детектирует
объекты, пересчитывает пиксели в миллиметры базы робота и передает массив
координат в контроллер KUKA (KR C4 + KUKA.Ethernet KRL) по TCP/IP.

## Состав проекта

| Файл | Назначение |
|---|---|
| `calibration.py` | Внутренняя калибровка камеры по ArUco GridBoard (раздел 1 ТЗ) |
| `vision.py` | CV-пайплайн: дисторсия → предобработка → контуры → minAreaRect (раздел 2) |
| `field_calibration.py` | Калибровка поля: пиксель → база робота по 4+ реперным точкам (раздел 3) |
| `server.py` | TCP/IP-сервер для KUKA EKI, XML-протокол (раздел 4) |
| `gui.py` | Графический интерфейс оператора (Material Design): просмотр, детекция, калибровки и сервер |
| `kuka/VisionConfig.xml` | Конфигурация EKI для контроллера |
| `kuka/VisionPick.src` | Пример KRL-программы Pick & Place (раздел 5) |
| `test_pipeline.py` | Синтетический тест всей цепочки без камеры и робота |
| `test_fixes.py` | Регрессионные тесты исправленных дефектов (29 проверок) |

Результаты калибровок: `camera_calibration.npz` (камера),
`field_calibration.npz` (поле).

## Графический интерфейс

Все режимы собраны в одном окне в стиле Material Design (customtkinter):

```bash
pip install customtkinter pillow   # единственные зависимости GUI
python gui.py                      # python gui.py --camera 0 — сразу камера
```

- **Шапка** — статус-чипы: калибровка камеры, калибровка поля, состояние
  сервера (остановлен / слушает порт / отвечает).
- **Источник** — индекс камеры, путь к видео или снимку; Enter — подключить.
- **Просмотр** — живой кадр с рамками, центрами и углами; под ним таблица
  деталей с пересчетом в мм (двойной клик или правая кнопка — копирование
  координат в буфер).
- **Детекция** — все параметры пайплайна (`min-area`, аспект, заливка,
  HSV, полярность и т.д.) меняются на лету, в том числе при работающем
  сервере — детектор общий. Кнопка сброса возвращает значения по умолчанию.
- **Поле (мм)** — калибровка поля кликами: «Добавить точку кликом» →
  клик по кадру → ввод X,Y робота с пульта (последнее значение
  подставляется автоматически); Ctrl+клик добавляет точку из любой
  вкладки. «Рассчитать и сохранить» записывает `field_calibration.npz`.
  Переключатель проверки показывает координаты под курсором прямо в кадре.
- **Камера** — ракурсы ArUco GridBoard кнопкой вместо SPACE, счетчики
  видимых маркеров и ракурсов; после расчета матрица сразу применяется
  к детекции.
- **Сервер KUKA** — запуск/остановка TCP-сервера, статус, журнал обмена
  XML с подсветкой. Поля хоста/порта блокируются во время работы.
  «Тестовый захват» прогоняет ту же цепочку без робота — удобно для
  проверки перед включением KRC.

Консольные команды ниже продолжают работать как раньше.

## Порядок ввода в эксплуатацию

### 1. Калибровка камеры (уже выполнена)

```bash
python calibration.py --camera 0
```

Снимите 15–20 ракурсов доски 12×18 ArUco (SPACE), затем `C`.
Выход: `camera_calibration.npz` / `.yaml` — матрица камеры и дисторсия.
Каждый входящий кадр в пайплайне исправляется через `cv2.undistort`.

### 2. Настройка детекции

```bash
python vision.py --camera 0
```

Живой просмотр: рамки, центры и углы деталей. Основные параметры:
`--min-area` (отсечение мусора), `--aspect-min` (квадратность),
`--hsv-low/--hsv-high` (цветная сегментация вместо Оцу), `--adaptive`,
`--symmetry` (диапазон угла; 90 → [-45, +45]).

### 3. Калибровка поля

1. Разметьте на столе робота минимум 4 реперные точки.
2. Острием инструмента коснитесь каждой точки и запишите координаты
   X, Y в базе робота с пульта KUKA.
3. Запустите и кликните те же точки в окне в том же порядке:

```bash
python field_calibration.py --robot 350.2,-120.4 --robot 520.1,-118.9 \
    --robot 515.0,180.2 --robot 345.8,175.6
```

Клавиша `C` рассчитывает гомографию (`cv2.findHomography`) и сохраняет
`field_calibration.npz`; в консоль выводится погрешность по каждой точке
(должна быть порядка единиц мм). `V` — режим проверки: координаты мыши
в реальном времени пересчитываются в мм.

### 4. Запуск сервера

```bash
python server.py --camera 0 --port 59152 --part-height 15.0 --show
```

- `--part-height` — высота детали Z (камера дает только X, Y, A);
- `--show` — окно отладки с результатом детекции;
- остальные параметры детекции — те же, что у `vision.py`;
- `--camera` принимает и путь к видео/снимку (удобно для проверки).

Протокол: робот отправляет `<Trigger>Capture</Trigger>`, в ответ получает

```xml
<VisionResult>
  <Item Count="2">
    <Part Index="1" X="450.2" Y="-120.5" Z="15.0" A="24.8" />
    <Part Index="2" X="510.0" Y="-80.3" Z="15.0" A="-12.1" />
  </Item>
</VisionResult>
```

При ошибке возвращается `<Item Count="0" Error="..."/>`.

### 5. Сторона робота

Скопируйте `kuka/VisionConfig.xml` в
`C:\KRC\ROBOTER\Config\User\Common\EthernetKRL\` (укажите в нем IP ПК),
загрузите `kuka/VisionPick.src` и адаптируйте под ячейку: TOOL/BASE,
выход пневматики, высоты подхода и матрицу укладки.

## Проверка без оборудования

```bash
python test_pipeline.py   # сквозной тест цепочки
python test_fixes.py      # регрессионные тесты исправленных дефектов
```

Генерируется кадр с двумя «кубиками», проверяются нормализация угла,
детекция, пересчет в базу робота и полный TCP-обмен с XML-ответом.

### Важно: параметр `--polarity`

Полярность бинаризации ранее работала наоборот: `--polarity dark`
выделял фон вместо детали. Теперь смысл прямой:

- `dark` — детали темнее фона (темный кубик на светлом столе);
- `bright` — детали светлее фона;
- `auto` — объекты занимают меньшую часть кадра (по умолчанию).

Если в старых сценариях запуска стоял `--polarity bright` для темных
деталей как обходной путь, замените его на `dark`.

## Промышленная камера

Сейчас захват идет через `cv2.VideoCapture`. Для GigE/USB3 камер Basler
достаточно заменить `FrameSource` в `server.py` на `pypylon` —
остальная цепочка не меняется.
